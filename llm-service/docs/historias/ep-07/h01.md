## Descripción (Como / Quiero / Para)

- **Como:** operador del servicio (rol ADMIN o responsable de operación)
- **Quiero:** consultar en un panel el costo acumulado por función y período, las cuotas consumidas versus el límite configurado, y los errores y latencias del proveedor de modelos
- **Para:** detectar saturación, anomalías de costo o fallas del proveedor antes de que impacten a los alumnos

---

## Notas / Observaciones

- El panel es un endpoint REST autenticado; la interfaz visual (si existe) la provee el frontend y queda fuera del scope de este servicio.
- Los datos expuestos son métricas agregadas: tokens consumidos, costo estimado (USD), porcentaje de cuota utilizado, tasa de errores del proveedor y latencia p50/p95/p99. Nunca se expone contenido de prompts, respuestas individuales ni identificadores de alumnos.
- Las métricas se calculan sobre ventanas de: última hora, hoy, últimos 7 días, últimos 30 días (parámetro `period`).
- Si el proveedor está caído, el panel responde con las métricas cacheadas más recientes y devuelve el campo `"dataFreshness": "cached"` con el timestamp de la última actualización real.
- El caché tiene TTL configurable (por defecto 5 minutos). El acceso al panel no genera ninguna llamada en tiempo real al proveedor.
- Seguridad: solo tokens con scope `ADMIN` u `OPS` pueden acceder. Tokens de rol `TEACHER`, `STUDENT` o sin rol reciben 403.
- Los datos de costo son estimados a partir de tokens reportados por el proveedor y el precio configurado en `llm.provider.cost-per-1k-tokens`. No se accede a APIs de facturación externas.
- Todas las respuestas incluyen `Content-Security-Policy`, `X-Content-Type-Options` y cabeceras de no-caché para datos sensibles.

## Criterios de Aceptación (CA)

- [ ] **CA1:** `GET /api/v1/operations/dashboard?period=today` con token `ADMIN` devuelve HTTP 200 y un JSON con los campos: `period`, `functions` (array con `name`, `tokensConsumed`, `estimatedCostUSD`, `quotaUsedPct`), `providerErrors` (tasa de errores), `latencyP50Ms`, `latencyP95Ms`, `latencyP99Ms` y `dataFreshness`.
- [ ] **CA2:** El parámetro `period` acepta `last-hour`, `today`, `last-7-days` y `last-30-days`; un valor desconocido devuelve 400 con mensaje descriptivo.
- [ ] **CA3:** Los campos `tokensConsumed` y `estimatedCostUSD` están correctamente agregados por función (`tutor`, `evaluator`, `rag-ingest`, etc.) y el total coincide con la suma de los parciales.
- [ ] **CA4:** Cuando el proveedor está caído, la respuesta sigue siendo HTTP 200 con `"dataFreshness": "cached"` y el campo `cachedAt` con el timestamp ISO-8601 de la última lectura real.
- [ ] **CA5:** El campo `quotaUsedPct` refleja el límite configurado en ese momento; si el límite cambia, la siguiente ventana de caché refleja el nuevo porcentaje.
- [ ] **CA6:** Ningún campo de la respuesta contiene identificadores de alumnos, contenido de prompts ni respuestas individuales del modelo; cualquier intento de filtrar por `studentId` devuelve 400. Esta prohibición es de **este panel agregado**; no aplica al endpoint puntual de configurar el límite de un alumno (`PUT /api/v1/operations/quotas/student/{studentId}`, ver [h02.md](h02.md)), que es un recurso `ADMIN` distinto y no expone contenido ni historial del alumno, solo su límite vigente (ver [08 P-12](../../08-decisiones-y-pendientes.md)).
- [ ] **CA_negativo_1:** (caso que debe fallar) Un request con token de rol `TEACHER` o `STUDENT` al endpoint del panel recibe HTTP 403 con body `{"error": "forbidden", "requiredScope": "ADMIN|OPS"}`.
- [ ] **CA_negativo_2:** (caso que debe fallar) Si el panel intentara exponer un campo con PII de alumno (nombre, e-mail, ID de sesión individual), el test de contrato falla y el build se rompe.

## BDD

**Qué se prueba:** que el operador puede obtener métricas operativas agregadas, que el acceso está restringido por rol, y que el panel funciona con datos cacheados cuando el proveedor está caído.

### Escenario 1 — Operador consulta el panel del día (camino feliz)

- **Dado:** que existe un token JWT con scope `ADMIN` y hay métricas registradas para la función `tutor` en la ventana `today`
- **Cuando:** el operador hace `GET /api/v1/operations/dashboard?period=today` con el token ADMIN
- **Entonces:** el servicio responde HTTP 200 con `dataFreshness: "live"`, `functions[0].name: "tutor"`, `functions[0].quotaUsedPct` entre 0 y 100, `latencyP95Ms` mayor que 0, y ningún campo contiene información de alumnos

### Escenario 2 — Docente intenta acceder al panel (caso que debe fallar)

- **Dado:** que existe un token JWT con scope `TEACHER` válido
- **Cuando:** el docente hace `GET /api/v1/operations/dashboard?period=today`
- **Entonces:** el servicio responde HTTP 403 con `{"error": "forbidden", "requiredScope": "ADMIN|OPS"}` y no se registra ningún acceso a métricas internas

### Escenario 3 — Panel responde con métricas cacheadas cuando el proveedor está caído (caso que debe fallar el proveedor, no el panel)

- **Dado:** que el proveedor de modelos está caído (simulado con WireMock/Testcontainers), hay métricas en caché de hace 3 minutos, y el operador tiene token ADMIN
- **Cuando:** el operador hace `GET /api/v1/operations/dashboard?period=today`
- **Entonces:** el servicio responde HTTP 200 (no 503), `dataFreshness: "cached"`, `cachedAt` con timestamp de hace ≤5 minutos, y todos los campos numéricos tienen valores coherentes (no nulos ni negativos)
